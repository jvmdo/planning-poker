# 18: The Facilitator sets the Deck

**What to build:** Let the Facilitator choose which Cards the Room plays with. The Room starts with today's hours Deck. A "Deck" button in the status bar, shown only to the Facilitator, opens a dialog with presets and a free-input field, and a live preview of the hand. Applying a new Deck starts a new Round for everyone. Cards stay whole numbers of hours. User stories 54–57; the Room command, rejections and tests are in the spec under the Room module.

**Blocked by:** none

**Status:** ready-for-agent

- [x] **Shared contract:** `deck.ts` keeps today's list as `DEFAULT_DECK` and holds the Deck rules as constants (`MIN_DECK_SIZE` 2, `MAX_DECK_SIZE` 15, `MIN_CARD` 1, `MAX_CARD` 99), plus a pure function that turns free input into a Deck or into what's wrong with it. A `Card` becomes a plain `number`. The snapshot carries the Room's `deck`. A `setDeck(cards)` client-to-server event. Both the Room and the dialog use the same function, as `spendBurst` is shared for the burst limit.
- [x] **Deck rules:** 2 to 15 Cards; each a whole number from 1 to 99; duplicates removed and the Cards sorted ascending, without complaint. Anything else (a decimal, 0 or a negative, 100 or more, something that isn't a number, too few or too many Cards) is refused.
- [x] **Room:** a new Room starts with `DEFAULT_DECK`. A Deck the Facilitator set stays when everyone leaves, so the next meeting finds it; only a restart, which makes a new Room, brings back the default. `setDeck(by, cards)`: only the Facilitator, Observer or Voter; an invalid Deck is refused with a reason and changes nothing. An accepted Deck that differs from the current one discards the Round (Votes cleared, Reveal undone, Round number up), like `newRound`. One equal to the current Deck, in any order, is refused as `deck-unchanged`, so every Deck sent gets an answer. `vote` checks the Card against the Room's Deck, not the constant. A restart resets the Deck to the default, as ADR 0001 already accepts for everything else.
- [x] **Socket adapter:** translates `setDeck` into the Room command, ignoring a payload that isn't an array. Rejections go back to the sender only.
- [x] **The dialog:** opened from a "Deck" button in the status bar, next to Reveal and New Round, only for the Facilitator. It offers presets as one-click choices: **Hours** (the default, `1 2 4 6 8 10 12 16 24 32 64`), **Fibonacci** (`1 2 3 5 8 13 21 34`) and **Powers of two** (`1 2 4 8 16 32 64`). A text field takes the Cards separated by commas or spaces, starts filled with the current Deck, and picking a preset fills it in. The field's problems are shown as you type and keep Apply disabled. A preview shows the hand with the same sizing and fan as Voters' hands, as wide as the dialog allows. Apply says "This clears N Votes" when Votes have been cast, and gives the same instant feedback as New Round while it waits for the server.
- [x] **Everyone's hand** follows the Deck in the snapshot. When the Deck changes, a short notice tells everyone but the Facilitator "The Facilitator changed the Deck". The Room tells a separate subscriber who changed the Deck, and the adapter broadcasts it as a `deckChanged` event; the client keeps nothing to compare.
- [x] **The hand fits any Deck size.** The hand is a container, and the Card width comes from its inline size and the number of Cards (roughly `min(118px, 10.5vh, 100cqi / N)`, keeping the current overlap), so it also grows when the sidebar collapses. With 11 Cards it looks as it does today. The number's size follows the Card's width, and the "hours" label hides when a Card is too narrow for it.
- [x] **The fan** keeps the end Cards at today's tilt (±11°) and drop (about 22px) whatever the count, spreading the others evenly between, with no more than today's 2.2° between neighbours so a small hand doesn't splay out.
- [x] **The breakdown** orders its bars by the Room's Deck instead of the constant. The join screen's warm-up Cards keep `DEFAULT_DECK`, since there's no snapshot yet.
- [x] Nothing scrolls horizontally or is cut off at 1024×720, 1366×768 and 1920×1080, sidebar collapsed and expanded, light and dark, with Decks of 2, 11 and 15 Cards (including 15 two-digit Cards).
- [x] **Room tests** cover: the default Deck in a new Room; a set Deck kept after the last Participant leaves; each rejection (not the Facilitator, too few, too many, a decimal, a negative, 100, not a number) leaving the Room unchanged; duplicates and order cleaned up; a changed Deck discarding the Round before and after the Reveal, Round number included; an unchanged Deck refused; the Deck change subscriber called once, with who; a Vote for a Card only in the old Deck refused, and one only in the new Deck accepted; an Observer Facilitator setting the Deck. Unit tests for the shared parsing function.

**Notes:**

- We target modern browsers, so modern CSS is welcome: container queries and `cqi` units, and `sibling-index()` / `sibling-count()` or CSS `@function` for the fan and the Card width if they work in current Chrome, Firefox and Safari when this is built. Otherwise pass the index and count as custom properties inline.
- The unit is still hours (`GLOSSARY.md`, Estimate). Presets are hour scales, not story points.
- A pending Vote for a Card the new Deck doesn't have is already dropped, because changing the Deck moves the Round number on (ticket 10).

## Comments

**Implemented (2026-10-30).** All criteria are met. Notes:

- **Decision:** the Deck is kept when the Room empties, so the next meeting finds the one the Facilitator set. Only a restart, which makes a new Room, brings back the default.
- **Shared:** `deck.ts` holds `DEFAULT_DECK`, the limits, `toDeck` (the Room's check of untrusted values), `parseDeck` (the dialog's reading of typed text, which also lists the words that aren't Cards) and `sameDeck`. A `Card` is now a plain `number`.
- **Room:** `setDeck(by, cards)` with the rejections `not-facilitator`, `not-a-card`, `too-few-cards` and `too-many-cards`. The snapshot carries `deck`. The two hidden-Vote tests now search everything in the snapshot but the Deck, which lists every Card for everyone. 24 new tests (20 for the Room, 10 of them one rejected Deck each, and 4 for `parseDeck`); 99 in all.
- **Client:** `deck-dialog.tsx`, a native `<dialog>` opened by the "Deck" button in the status bar. A changed Deck is a pending command like New Round: the buttons wait until the next Round's snapshot. The client sends only a Deck that differs from the Room's, since the server doesn't answer the same Deck with a snapshot. Everyone but the Facilitator gets the "changed the Deck" notice, spotted by comparing snapshots.
- **The hand:** `.card-hand` in `index.css` is an inline-size container. The Card width is `min(var(--hand-card-width), 100cqi / (var(--deck-size) + 0.5))`, so it never grows past today's size (the hand's height is made for it) and shrinks when the Deck needs room. The fan uses `--index` and `--deck-size` set inline, with `min()` capping the step at 2.2° and the drop at today's 0.9px per step². `sibling-index()`/`sibling-count()` weren't used, on the mistaken belief that Firefox lacked them; MDN's data shows Chrome 138, Firefox 154 and Safari 26.2 support them. (`@function` is the one Firefox lacks.) The number's size is `clamp()`ed from the Card width, and `PlayingCard` is now a container that hides "hours" below 52px; its `showUnit` prop is gone (the join screen's small warm-up Cards hide it the same way).
- **Checked** in a browser on a production build. With the default Deck the hand matches the previous build (66px Cards, ±11°, 22.5px drop at 1024×720; 113px at 1920×1080). 15 two-digit Cards fit at 1024×720, 1366×768 and 1920×1080 with the sidebar collapsed and expanded, with no scrolling. The narrowest case, 1024 with the sidebar expanded, gives 44px Cards without the "hours" label. 2 Cards fan at ±1.1°. Problems show as you type and keep Apply disabled; a preset is marked pressed when the field matches it; Apply warns about the Votes it clears; Enter applies and Escape cancels. The other Voter's Vote was cleared and they saw the notice; the Facilitator didn't. The breakdown orders its bars by the Room's Deck. Light and dark themes.
- **Known gaps:** the preview is as wide as the dialog, not the Room, so with many Cards its Cards can be a little narrower than in the real hand. After a server restart the Deck goes back to the default, and the notice then says the Facilitator changed it.

**Follow-up (2026-10-30).** `MIN_CARD` raised from 0 to 1. A 0 Card worked, but it pulled the Result down hard and could be played to mean "I don't know", since there's no `?` Card. A 0 is now refused like any Card outside the range; the dialog's hint follows the constant.

**Follow-up (2026-10-30).** The hand now uses `sibling-count()` and `sibling-index()` instead of `--deck-size` and `--index` set inline, so `CardHand` passes nothing to the CSS. Each Card's wrapper takes the width and is a container itself, and the button sizes its number with `cqi`, because those functions measure the element whose style uses them. Every child of `.card-hand` must be a Card. Measured in Chromium: the same widths, number sizes, tilt and drop as before at every size above. Not yet checked in Firefox or Safari.

**Follow-up (2026-10-30).** The dialog's preview is now centred vertically. Its box is as tall as the Room's hand, but its Cards are capped by the dialog's width, so on wide screens they sat at the top with up to 91px below them. Each Card now takes a bottom margin equal to its fan drop (`--drop`), so the hand's height is the fan's; the preview gives `CardHand` a `className` that lets it shrink to that height, and its box centres it. Measured in Chromium at 1024, 1366 and 1920 with 2 to 15 Cards: the space above and below now differs by 5px at most, the corners of the tilted end Cards. The Room's hand still aligns to the top and measures as before.

**Follow-up (2026-10-30).** The dialog now stays open while a Deck waits on the server. Apply shows the spinner New Round and Reveal use (moved to `waiting.tsx`), and the field, the presets and Cancel are disabled; Escape and clicks on the backdrop do nothing. It closes when the Room's snapshot carries the Deck it sent. If the command is refused or the connection drops first, the spinner stops and it says "The Deck wasn't changed. Try again."; editing clears that. Checked with `SIMULATED_LATENCY_MS=1000`: locked with the spinner showing at 400 ms, still open after Escape and a backdrop click, closed after about 1.4 s with the new hand. Stopping the server while a Deck waited showed the message and unlocked the dialog.

**Review fixes (2026-10-30).** From a two-axis review (standards and spec):

- **No client-side Deck memory.** The "changed the Deck" notice now comes from a `deckChanged` event (who changed it) that the Room passes to a new `subscribeToDeckChanges` subscriber and the adapter broadcasts, like Reactions and Throws. The `lastDeck` ref is gone, so the client keeps no Room state beyond the snapshot. A restart sends no event, so the false notice after one is gone too.
- **The same Deck is refused** as `deck-unchanged` instead of accepted silently, so every `setDeck` gets either a new Round's snapshot or a rejection. The client no longer has to know that the server stays quiet, and its own same-Deck guard is gone; the dialog still disables Apply for it.
- **Hidden-Vote tests:** the helper that searches a snapshot without its Deck now also checks the Deck is exactly the default, so Votes leaking into it would fail them. The spec's Testing Decisions say so.
- **`parseDeck` tests** stay, as a named exception in the spec's Testing Decisions: the dialog alone reads typed Cards.
- **Smaller:** `isCard` renamed `inDeck`, `DeckProblem` renamed `InvalidDeckReason`; the three pending commands are listed once (`PENDING_COMMANDS` in `pending.ts`); `reveal`, `newRound` and `setDeck` share `startCommand` instead of `setDeck` copying `sendCommand`; the adapter's broadcasts share `joinedSockets()`; the after-Reveal Deck test checks the Round number; long comment lines rewrapped.
- **Kept on purpose:** the round panel counts `hasVoted` over all Participants for "clears N Votes", separately from `played` (Voters only), because after the Reveal an Observer can still hold a revealed Vote.
- **Spec wording:** the preview is described as using the same sizing as Voters' hands, as wide as the dialog allows, rather than "exactly as Voters will see it".
- **Browsers:** `sibling-index()` checked in Firefox by the user. Safari not yet checked.
- **Tests:** 101 in all. The Deck block has 12 tests, one of which runs 11 rejected Decks, plus 4 for `parseDeck`. (The earlier count of "20 for the Room" is out of date.)
